What This Project Is

A Portfolio That Is Also a Project

This portfolio is not just a showcase — it is itself a demonstration of the skills it documents. It was designed from scratch, built with clean HTML and CSS, hosted on GitHub Pages, connected to AWS Amplify for automatic continuous deployment, and updated through a real CI/CD workflow. Every time content changes, a git commit triggers an automatic rebuild and deployment within 2–3 minutes.

The deliberate choice to use plain HTML and CSS — rather than React, Vue, or any other framework — was a technical and philosophical decision. A framework adds kilobytes, dependencies, and complexity. A portfolio viewed by a recruiter on a mobile connection should load instantly. Simplicity is a form of professionalism.

Exactly How I Built and Deployed This

Complete Build Process

1

Create GitHub Account and Repository

Created a GitHub account and a repository named exactly bestmanugochukwu.github.io — this naming format is required by GitHub Pages. The repository name must match your GitHub username exactly. Set visibility to Public and initialized with a README.

2

Enable GitHub Pages

In the repository Settings → Pages → Source: Deploy from branch → main → / (root). GitHub Pages automatically builds from the root folder of the main branch and serves it at the public URL. SSL certificate is provisioned automatically within a few hours.

3

Design the Portfolio Structure

Planned the site before writing any code: what pages are needed (index, projects, spiritual, ethics, resume, contact), what sections each page needs, what the color palette and typography should be. The entire design system — navy, gold, cream — was planned upfront in a single style.css file with CSS custom properties (variables).

4

Build All HTML Pages with Semantic Structure

Wrote each page using clean semantic HTML5 — nav, section, header, footer elements. All pages share the same navigation bar, the same CSS file, and the same footer. Content was written in a separate document first, then pasted into the HTML to avoid writing directly in code and making mistakes.

5

Implement Responsive CSS with Mobile Support

Built the entire design system in CSS using custom properties for colors, CSS Grid and Flexbox for layouts, and media queries for mobile responsiveness. Added touch-action: manipulation to all buttons to eliminate the 300ms tap delay on mobile devices.

6

Upload All Files to GitHub

Used GitHub's web interface to upload all HTML and CSS files directly to the root of the repository. Files are placed in the root folder — not inside any subfolder — because GitHub Pages looks for index.html at the root. After upload, GitHub Pages rebuilds the site automatically within 1–2 minutes.

7

Connect AWS Amplify for Automatic Deployments

In the AWS Amplify console, created a new app, connected it to the GitHub repository using OAuth authorization, selected the main branch, and configured the build settings with a minimal YAML file (since this is a static site with no build step). Amplify now monitors the GitHub repository — every push triggers an automatic redeploy within 2–3 minutes.

version: 1 frontend: phases: build: commands: - echo "Static site" artifacts: baseDirectory: / files: - '**/*'
8

Ongoing Updates — The CI/CD Workflow

Every update to the portfolio follows the same workflow: edit the HTML file in the GitHub web editor → commit changes → Amplify detects the push → rebuilds and deploys within 2–3 minutes → live site reflects the update. This is CI/CD applied to a personal project — the same pipeline principle used in enterprise DevOps, scaled down to one person.

Technical Decisions

Why I Built It This Way

Plain HTML/CSS Over a Framework

React, Next.js, and Vue would have added hundreds of kilobytes to every page load. A portfolio is a marketing document — it must load instantly on any connection. Plain HTML loads in milliseconds. The technical choice reflects the professional understanding that the right tool for the job is not always the most powerful one.

GitHub Pages + AWS Amplify — Two Hosting Layers

GitHub Pages provides the primary URL (bestmanugochukwu.github.io) and is completely free with automatic SSL. AWS Amplify adds a second deployment URL, faster CDN delivery, and demonstrates real cloud hosting skills. Using both shows understanding of the full deployment stack.

CSS Custom Properties for Maintainability

Every color in the site is defined once as a CSS variable (--navy, --gold, --cream). Changing the entire color scheme requires editing 4 lines. This is the same principle as environment variables in a cloud application — define once, use everywhere, change in one place.

Clickable Project Detail Pages

Rather than just listing projects, every major project links to a dedicated detail page with architecture diagrams, the exact commands used, problems encountered and how they were solved, and lessons learned. This mirrors how engineers document work in production — not just what was built, but how and why.
